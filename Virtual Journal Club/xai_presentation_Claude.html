Part 1 — The Problem

Why accuracy alone isn't enough

A model can be 96% accurate and completely wrong about why.

The Clever Hans problem

A model trained to detect pneumonia from X-rays learned to recognize hospital ID tags in the corner — not lung tissue. 96% accurate. Completely useless clinically.

Google Images, 2015

Searching "CEO" returned women only 11% of the time despite real-world representation of 27%. The model learned bias from training data — invisibly.

Loan denial (GDPR)

EU law requires any automated decision affecting a person to be explainable on request. A neural net prediction alone cannot satisfy this — legally.

"Just having a highly accurate model is not sufficient to trust and deploy the model in real-world applications."

— Dwivedi et al., 2023
Three things accuracy metrics miss
  • What the model actually learned — could be spurious correlations
  • Whether reasoning is fair — bias may be invisible in aggregate metrics
  • Why a specific decision was made — needed for audits and appeals

Part 1 — The Problem

Student question: Is XAI just a methodology?

"If I can run a neural network and then run SHAP without knowing XAI — what has XAI told me new?"

1 — Unified vocabulary

Before XAI, SHAP, LIME, and saliency maps were scattered across different research communities. XAI packages them with consistent terms: global vs. local, model-agnostic vs. specific, post-hoc vs. intrinsic.

2 — Legal obligation

XAI defines when explanation is legally required — not just technically possible. GDPR, healthcare regulation, financial audits. A data scientist running SHAP for curiosity vs. for compliance is a different act.

3 — Catches what accuracy misses

XAI is the only framework that systematically checks whether a model's reasoning is valid — not just its output. This is the Clever Hans problem. You can't find it without an explanation tool.

Short answer: XAI is not a new algorithm. If you already use SHAP on your neural network, you are already doing XAI. What XAI adds is the structured argument that you are obligated to do it in certain domains — and the taxonomy of which tool answers which question.

Part 2 — The Methods

SHAP — the workhorse of black-box explanation

Game-theoretic: asks "what is each feature's fair contribution to this prediction?"

The core idea

For each prediction, compute the average marginal contribution of a feature across all possible subsets of features. The result φᵢ is that feature's "Shapley value" — its fair share of credit for the prediction.

The additive property

∑ φᵢ = f(x) − E[f(x)]

All SHAP values for one prediction always sum exactly to the prediction's deviation from the dataset mean. This is mathematically guaranteed — unlike LIME.

Tree SHAP

Exact values. Fast. Only works on tree-based models (XGBoost, RF).

Kernel SHAP

Approximate. Works on any model including neural nets. Slower.

Part 2 — The Methods

LIME — local approximation of any black box

Explains one prediction by building a simple interpretable model in its local neighborhood.

1
Take one data point to explain

The specific instance whose prediction you want to understand — e.g. one loan applicant.

2
Perturb the input hundreds of times

Slightly modify feature values, run each through the black-box model, collect predictions.

3
Fit a local linear model on those samples

Weight samples by proximity to the original point. Fit a simple linear regression to approximate behavior locally.

4
Read off the linear coefficients as explanation

Coefficients of the local linear model = feature contributions for that one prediction.

LIME vs. SHAP — when to use which
LIMESHAP
SpeedFasterSlower (Kernel)
StabilityCan vary between runsConsistent
AdditivityNot guaranteedAlways sums to f(x)−E[f(x)]
Best forQuick explorationFinal reporting

Key limitation: LIME defines "neighborhood" arbitrarily. Two runs on the same instance can give different feature weights. Use SHAP for anything you're going to show a stakeholder.

Part 2 — The Methods

SHAP global feature importance

Aggregate local explanations across the whole dataset to understand overall model behavior.

How it works
  • Step 1: Compute local SHAP values for every row → N×F matrix of φᵢ values
  • Step 2: Take mean |φᵢ| per feature across all rows
  • Step 3: Rank features by that mean absolute value
Why absolute value matters

Income pushes some predictions up (+0.73) and others down (−0.18) — but its average |φ| = 0.45 still ranks it as an important feature. Signs cancel; magnitude is preserved.

SHAP vs. sklearn feature_importances_

Built-in Gini importance is biased toward high-cardinality features. Tree SHAP gives unbiased, exact values. Always prefer SHAP for final reporting.

Student question: which method do I run and when?

"After running a neural network, to answer the question of reasoning — SHAP, LIME, or something else?"

Your model Your question Use this Why
Neural net Which features matter overall? Kernel SHAP — global No built-in importance; SHAP is model-agnostic
Neural net Why was THIS prediction made? SHAP waterfall Additive, stable, auditable — use for stakeholders
Neural net Quick exploration / what-if? LIME Faster; unstable so don't use for final reporting
XGBoost / RF Which features matter overall? Tree SHAP — global Exact, fast — do NOT use sklearn .feature_importances_
XGBoost / RF Why was THIS prediction made? Tree SHAP — local waterfall Exact Shapley values, polynomial time on trees
Logistic reg. Which features matter overall? Coefficients directly White box — β IS the explanation. No add-on needed.
Logistic reg. Why was THIS prediction made? β·x per instance Multiply coefficient × feature value per row. Exact.
Any model Is the model biased / fair? SHAP beeswarm Check if protected attributes rank high in mean |φᵢ|

Rule of thumb: SHAP for anything that goes to a stakeholder or audit. LIME for quick interactive exploration. Coefficients if you're still on a white-box model.

Part 3 — The Takeaway

What this paper actually contributes

Not a new algorithm

XAI does not invent SHAP, LIME, or PDP. These already existed. XAI is the framework that organizes them, names the problem they solve, and defines when you are obligated to use them.

A taxonomy you can actually use

Global vs. local, white box vs. black box, model-specific vs. agnostic. These three axes let you navigate from "I have this model and this question" to "I should use this tool" without guessing.

Accuracy ≠ trustworthiness

The paper's central empirical argument: high accuracy is a necessary but not sufficient condition for deployment. XAI provides the second check — is the reasoning valid?

"Model performance metrics do not always exhibit true prediction decisions. Just having a highly accurate model is not sufficient to trust and deploy the model."

— Dwivedi et al., 2023
The three things XAI gives a data scientist
  • Debugging: find Clever Hans behavior before deployment
  • Compliance: satisfy GDPR and domain-specific audit requirements
  • Communication: explain model decisions to non-technical stakeholders, regulators, and affected users
